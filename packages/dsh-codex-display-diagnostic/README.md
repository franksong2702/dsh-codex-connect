# Single-session display diagnostic (experimental)

This separately installed, default-off package can send one fixed, non-approval question through the existing `UserQuestions.ask` → Remote Gateway → question composer chain. It uses an existing registered, idle, live root; it never creates or drives an agent, calls a model, invokes CUA/native input, modifies grants, or fabricates an approval. Its answer is ignored and cannot authorize anything. The diagnostic is consumed after one attempt, is cancelled after at most 60 seconds, and closes on plugin disposal, root replacement, user activity or owner-Peer loss.

The Host route accepts only the existing authenticated browser Peer over loopback with an exact same-origin POST and same-origin browser fetch metadata. The target session is fixed in local plugin configuration, never supplied by the caller. A running root, pending question or unavailable/replaced session fails closed. No new credentials or remote access are provided. The browser observes the existing event handler and pending/card state without registering an answering subscriber. It emits only bounded numeric counters and booleans into its local diagnostic panel; no question body, session/target identity, URL, typed data, answer or credential is recorded. `lastObservation` represents the last observation made while the probe was active, not necessarily the current DOM after stopping. The `outcome` only describes this inert diagnostic and is never an authorization decision.

The package is not part of the ordinary Connect installation and is pinned to `0.2.2-alpha.2.codex-cua-local.9`. After a separate deployment decision and review, an operator would install this private package only into the designated instance and explicitly enable it with the single known test session ID. Once the same authenticated browser opens that session, the panel can issue the one inert diagnostic. Afterwards disable/uninstall this package; the diagnostic cannot be reused in the same plugin lifetime. No configuration, permission database, OS setting or grant should be changed by the package. The currently running instance has not been updated with it.

Validation: `node --test packages/dsh-codex-display-diagnostic/test/*.test.mjs`, `node scripts/build-display-diagnostic.mjs --check`, and `node scripts/check-display-diagnostic.mjs <isolated-local9-candidate>`. The last uses a temporary real production Host and frontend, synthetic authentication/root, inert CUA/model providers and a bootstrap-context exposure solely for the production session navigation call. Gateway, question, and diagnostic bundles are not rewritten. It checks owner/source rejection, one question, receive/dispatch/pending/mount/viewport, cancellation and cleanup. It does not reproduce the historical missing-card event or prove real-user display, native control, approval, or performance parity.
