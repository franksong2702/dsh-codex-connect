# Codex Connect — Images

English | [中文](docs/README.zh.md)

Optional image generation for [Codex Connect](https://www.npmjs.com/package/dsh-codex-connect) in DeepSeek Harness.

This package is a private implementation preview. When enabled beside a compatible Codex Connect core, it registers `codex_connect_image_generate`. The tool accepts only a text prompt, asks the core transport for one bounded image response, validates PNG/JPEG/WebP bytes against the active DSH attachment limits, and stores the validated batch as durable attachments. DSH now shows the result through its native image gallery and lightbox, with a download action and a dedicated Plugin settings card. The release workflow and authorized 3081 smoke test are still pending, so do not publish it as a finished plugin.

The completed add-on will remain a separate npm package so users can keep the core Codex Connect provider without installing image generation. Images are generated by the Codex upstream endpoint. The upstream decides which model runs; this plugin does not specify it and makes no claim about it.

## Browser experience

- The Plugin settings card can enable or disable **new** image calls; previously generated images remain available in conversation history.
- A running card says that generation typically takes 13–23 seconds and normally returns one PNG.
- Completed calls use DSH's native `ImageGallery` and `ImageLightbox`; attachment bytes are loaded through the current session rather than through provider URLs.
- Failure and cancellation cards use fixed, redacted copy. Canceling local waiting does not prove that upstream generation stopped.
- The settings card reads only the core plugin's same-origin status category. It never displays account IDs, OAuth URLs, tokens, local paths, or raw upstream errors.

## Safety boundary

- Community Alpha; not endorsed by DeepSeek or OpenAI.
- No credentials, account IDs, OAuth URLs, or full prompts belong in issues or logs.
- The add-on will not change the default model or search route.
- Image generation may consume additional quota, and cancellation may stop only local waiting. If cancellation races with attachment storage, the content-addressed store may retain an unreachable object even though the conversation receives no attachment reference.
- The tool retries zero times, never logs the full prompt or encoded image body, and returns only text plus opaque attachment references to the model.
- A rejected batch returns no partial attachment references. The underlying content-addressed store may retain unreachable objects after a storage failure or cancellation race.
