# Local Host candidate — not a published DSH release

Base: the actual published npm package set `0.2.2-alpha.2`. The current candidate identity is `0.2.2-alpha.2.codex-cua-local.10`; the directory name retains the patch lineage. This directory contains public-source diffs and synthetic tests only. No native binary, device configuration, account data or credentials is committed. No upstream PR or release is authorized by this work.

Local.3 fixes first-use target selection before task consent. The existing Computer Use plugin settings contain an operator-only task-window selector: supply the intended root conversation ID and one exact already-running application selector, discover bounded window metadata, and select a window. The three RPCs require the authenticated invocation's actual owner principal; a missing invocation and permitted non-owner remote peers are rejected. They are not CUA/model tools. Selection lasts at most two minutes, grants no application access, and is consumed once by the genuine root/owned child. The private native connection retains process-start identity and the selected AX window-object identity (window identity metadata only, no page tree/content), rejecting process or window-ID reuse. It moves intact into the child's standard CUA pipeline; identity is checked again before and after the human answer and at native AX/pointer dispatch. Missing existing OS Accessibility access blocks; the selector never requests or changes it.

Selection exposes only application/window metadata, no native handle or authorization. The root's actual task card is still mandatory before observing page content or dispatching input. Clear/expiry/root disposal close unclaimed connections; cancellation, refusal and completion close claimed task connections. The UI only reports a clear after a confirmed response. The original application grant store, root guard, existing legacy fixed-target mode and local.1/local.2 diagnostics remain unchanged. Source/synthetic tests do not establish GUI acceptance or performance parity.

Local.2 adds the [single-task human consent contract](delegated-task-design.md). Its process-local Host service validates genuine root/owned-child identities and obtains a root-owned user-question answer before returning a usable native application handle. Host dispatch independently enforces the fixed application, window, operation and latest strict snapshot. Task close leaves a weak tombstone so a still-live child cannot fall back to stored grants. Stop, revocation and expiry cancel work; denial or a dismissed question prevents another worker for the same user input. The task reads only the shared revocation generation under the existing application lock, including after a human answer, so another Host's revoke remains authoritative. It neither uses stored allow decisions to grant a task nor saves a task application grant. Missing consent remains blocked. The existing root guard and native AX code are unchanged.

The first local.2 actual-Host composition run passed 30 scripted tests, including real root-question admission, denial, malformed answers, task boundaries, in-flight revocation, expiry and tombstone behavior. These use synthetic channels and answer fixtures, with no real model, OS permission, desktop input or live human approval. Full exact-source CI/review and live human acceptance remain gates. The local.1 checkpoint below is historical.

`manifest.json` records original npm integrity, exact before/after file hashes and patch hashes. The builder verifies the complete 321-package closure against `published-lock.json`, verifies each tarball SHA-512, and compares all copied files and executable bits before applying zero-context diffs with `patch -p1 --fuzz=0`. The original published installation is retained separately. A local candidate must carry its own version and source identity; it must never be described as the unmodified npm release.

The route extension runs `agent/route-request` before choosing tools and assembling the prompt. Its complete configuration is captured for the request. The existing `agent/request` invariant still prohibits later route changes. A quota-recovery listener can explicitly request `reprepare:true`: the same failed step rebuilds its route/tool/prompt world without submitting the original input again. Ordinary retries keep their existing prepared world. The live AgentRegistry advertises `requestRoutingVersion=1`; Codex Connect uses that live service rather than an independently installed older SDK copy's exports. Older Hosts retain the old route waterfall.

The CUA extension is opt-in (`strictWindowScope`, default false). Strict observations exclude application-global/menu roots, require live per-element target-window equality, and stamp the snapshot with the strict policy. Indexed actions resolve that stored policy and check live ownership again at mutation, including delayed AXRaise. Indexed pointer fallbacks carry the strict snapshot window through route creation and pointer validation; AX hover actions receive the same constraint. Public results preserve the strict-window attestation in every bundled state parser. Ordinary application-scoped CUA behavior retains its default. These are local source changes pending installed-Host and independent review, not proof of native acceptance.

Its runtime manifest pins both npm and pnpm overrides to the local package directories. It never installs into a daily profile or launches a native helper. `build-evidence.json` records the current native build hash and explicitly incomplete integration evidence. `route.test.mjs` is a scripted real-Host regression, not a model or GUI acceptance test.

The local.4 operator-only instance step filters the exact requested bundle inside the provider. It retains private native process handles, exposes only bounded identity candidates, and uses the chosen handle for window metadata. A PID is never a grant. The normal model CUA schema is unchanged. The settings panel can take the current conversation from the public Session source; no session URL format is assumed.

On a non-Darwin validation host, only the known Darwin-only optional backend may remain uninstalled and be materialized as source. On Darwin, that backend must be installed; it is resolved through its owning bundle, including strict pnpm layouts. The builder obtains optional source from the exact integrity-locked official archive and validates the same private snapshot before extraction. It preserves the fixture's direct roots and overrides-only pins, leaving published optional edges and optional peers under their original package manifests. Required paths are recomputed from the verified original metadata and must still be installed and byte-verified. This source-only preparation neither executes the native backend nor proves desktop compatibility on Linux.

The local.5 native correction verifies regular executable files by pinned read-only descriptors and device/inode identity, allowing distinct paths only when they name the same file. It samples process identity and the kernel executable path before and after use, and rechecks path bindings while the original descriptors remain open. Missing or unreadable paths, different files, process changes and path replacement fail closed. It does not use clone-path prefixes, content hashes, file sizes or bundle identifiers as substitutes for file identity, and changes no consent or window scope. The synthetic Swift fixture exercises real temporary-file metadata and replacement failures without a desktop or application.
