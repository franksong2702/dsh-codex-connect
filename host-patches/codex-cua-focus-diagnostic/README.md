# Focus failure diagnostic overlay — local.9 baseline and local.10 candidate

The real local.9 failure reached Native `authorizeTaskInput` after the task consent gate and returned `CUA_INPUT_FOCUS_LOST`. The saved terminal projected the Native code but discarded the error message. The current evidence does not establish whether focus failed during convergence or the final recheck, nor whether the user moved focus or input.

The local.9 Native implementation already emits three different fixed strings for convergence timeout, final AX window mismatch and final foreground-process mismatch. NativeClient constructs `NativeError(reply.error.code, reply.error.message)`. This small overlay maps **only exact matches** of those fixed strings, for Native errors in the arm stage, to the finite `focus.phase` values `settle_timeout`, `final_ax`, or `final_foreground`. Existing `CUA_INPUT_USER_TAKEOVER` stays separately mapped to `hardware_changed`. It preserves the original error code, stage, closed guard, cause chain and cleanup behavior. It never records the message, process/window identity, titles, coordinates, input, hardware counters or credentials. Unknown or decorated messages remain unclassified; output is never permission or approval.

The Native overlay also addresses two bounded preparation defects. First, focus observation now requests the explicit on-screen, front-to-back WindowServer list; the full directory has no such documented ordering guarantee. All other directory callers keep their original options, and all four process/window comparisons remain mandatory. Apple's [on-screen option documentation](https://developer.apple.com/documentation/coregraphics/cgwindowlistoption/optiononscreenonly) and the SDK `CGWindow.h` document the ordered list. A synthetic WindowServer fixture runs the exact old/new production methods against a directory whose order differs from the on-screen order, and verifies foreign and missing front windows still fail the matching conditions.

Second, when activation is necessary, preparation waits for the selected process to become foreground **before** its one permitted AXRaise. Activation can finish asynchronously and otherwise restore a previous window after an early raise. A single shared one-second cooperative budget, cancellation, identity checks, HID takeover checks, the four-way final observation and final arm check remain. There is no re-activation, repeated raise or weakened guard. An exact-method synthetic fixture models delayed activation and verifies the old order fails, the candidate succeeds, and user takeover/cancellation stop before the raise. Neither fixture proves what caused the historical live failure.

This overlay is incorporated in the unpublished local.10 candidate; it is not an official Host release or evidence of live acceptance. `node scripts/check-focus-diagnostic.mjs <isolated-local9-or-local10-candidate>` verifies exact baseline/result hashes, applies the overlay in temporary storage, checks Host/companion projection parity and the NativeClient/Swift source contracts, and tests the actual patched projection against the old baseline, all three branches, HID reason and hostile strings. On macOS it also runs the two synthetic old/new Swift fixtures. `node scripts/check-focus-native-build.mjs <isolated-local9-or-local10-candidate>` verifies all 33 baseline Native source hashes, applies the three Native overlays, repeats the fixtures and compiles the complete helper without executing it. No Native helper, OS input or model is run. The actual historical Native message was not saved, so this cannot determine which branch failed in that test.

Before use in any future candidate, incorporate the reviewed overlay in a distinctly identified Host/companion build, verify complete source provenance, package hashes and rollback, then separately authorize any deployment and live test. The three-way classification does not identify which of the four focus-convergence conditions differed, or whether the user caused it. Do not weaken checks, add blind retries or claim the historical focus failure is repaired based on these synthetic tests.
