# 实验性 Astra 推理档位调整

本实验仅包含在经过审查的 PR #167 构建中，已发布的 Alpha 4.33 不含此功能。请使用隔离测试环境，配对 DSH `0.1.2-rc.1` / pi-ai `0.84.4` 或 DSH `0.1.5-alpha.1` / pi-ai `0.85.1`，不要混用不同版本的宿主包。具体安装提交和验证结果见 PR。

此功能默认关闭，供测试使用。它通过 Astra 的 `configuration_update` 输入项调整后续请求的推理档位，不修改请求级初始档位。不保证缓存复用、输出质量、订阅用量或账户可用性。

## 测试方法

1. 在测试用 DSH profile 安装 PR 构建，保持日常 profile 不变；此 PR 不是 npm 发布。
2. 在设置 → 插件 → 插件配置 → Codex Connect 中启用**实验性 Astra 推理档位调整**并保存。对应插件配置为 `enableReasoningUpdates: true`。
3. 新建 GPT-6 Astra 会话，显式选择 `low`、`medium`、`high`、`xhigh` 或 `max`，不要选择 Default。
4. 正常讨论一个需求，自然进入困难的设计或排障，最后做常规收尾。不要提推理档位，也不要点名工具；模型自身会收到主动建议的指导。
5. 观察 Astra 是否在合适时机提出有理由的调整、避免重复打扰并尊重拒绝。在原生问题中同意或拒绝提议。不要求必须调整，保持当前档位也可能合理；验收建议质量，而非调用次数。
6. 同意后继续任务，随后恢复同一会话再聊一轮。工具先报告排队，确认通知进入下一轮请求时才应用更新。DSH 记录该请求后，选择器显示生效档位，例如 High，不另列初始档位。发送协议所需的初始值由插件内部保留；实际请求档位需结合请求证据核验，不能把界面表现当作服务端执行证明。

开发侧链路检查可以明确要求调用 `codex_connect_set_reasoning_effort`，但它只能验证确认与重放流程，不能证明主动建议质量，不是主要用户验收方法。

Astra 在有实质意义的任务阶段转换时，评估下一阶段的未决问题和错误代价。根因不明、方案竞争、重大决策或推翻原计划的新证据，可以成为升档理由。原因、方案、范围和验收标准明确后，应主动考虑为局部实现、常规验证或后续整理降档。但不能仅因为已有计划就降档：并发、安全和数据迁移的实现仍可能困难。各阶段不绑定固定档位。不需要调整时直接继续任务，不额外提问；工具调用本身不触发重新评估，没有实质变化或新证据时，不重新争论用户拒绝或手动选择的档位。提议应简短说明接下来做什么、情况有何变化、为何适合目标档位。目标兼顾可靠完成、返工和用户时间，不承诺质量或额度收益。Harness 不计算任务难度，也不决定档位；工具提议仍须人工确认，显式手动选择优先。

首次进入请求及通知变化时，会话记录中加入初始与有效档位及简短策略提醒；完整策略集中在工具说明中。恢复会话时保留通知，相同通知不重复追加。Default 会明确报告为未显式选择初始档位，而非猜测。无密钥请求快照验证策略确实送达，不代表模型判断正确或实际省额度。

拒绝不会调整档位。在通知正式进入请求前取消，可能丢弃排队通知。关闭开关会移除新提议能力并取消待答问题；已进入会话记录的确认仍继续重放，不会重置已有会话的有效档位。如不想再次确认调整，可新建会话。

## 限制与验证

首版仅支持当前主代理、原会话身份、完整且未压缩的历史，以及不变的供应方与模型。功能开启时，在原生选择器显式选择 Astra 档位，会在下一步记录为档位更新；以最后一次选择为准，包括调回初始档位，无需再次回答工具问题。若在本步上下文录入后再次改变选择，会在发送前拒绝，重试时可应用新选择。Default 和切换供应方或模型仍不支持。含确认记录的分叉会话、压缩、辅助模型调用、自动截断和服务端 previous-response 链接均拒绝执行；需要这些能力时请新建会话。profile 必须提供人工问题应答器。

无密钥测试组装真实 DSH 代理循环、模型选择钩子、工具运行时、用户问题服务、Codex 适配器和合成 SSE 传输，覆盖同意与拒绝、取消与卸载、并发手动选择、连续升降档、持久会话 JSON 恢复、原位置重放、默认设置不变和默认关闭设置。jsdom 测试加载已安装的 DSH 前端构建，验证真实 ModelDirectory 与 Composer 随投影值更新档位、重新挂载后保持显示；装饰图标和提示组件使用替身。这些测试不代表真实 ChatGPT 或已部署浏览器交互验收，后两项仍由用户测试验证。

## 实现说明

确认存入普通 `user/message` 事件，使用结构化的 `dsh-codex-connect` 插件来源元数据，并附带可见通知。不通过文本匹配授权，不修改默认设置，也不维护可变的会话覆盖表。DSH 的会话追加与恢复校验会保留元数据。正常 pi-ai 转换后，供应方公共 payload 钩子通过请求局部异步作用域插入更新，包含 prepared call 路径；守卫在发送前拒绝缺失或不一致的确认记录。

插件通过公开的 `agent/request` waterfall，在正常模型选择钩子完成后返回已确认的有效档位。DSH 将其写入 `request/header`，已有模型选择投影据此更新 Composer，并支持刷新与恢复。通知未正式进入会话或请求准备尚未完成时，不写入新请求头。请求头写入后的网络失败不会撤销已记录的配置；选择器表示配置档位，不表示远端执行成功。插件不调用会顺带保存默认选择的 `selectModel`。旧会话若仍记录初始档位，会在下一次请求时同步，仅打开历史不会迁移。供应方 payload 钩子从第一条确认通知取出固定的初始协议档位，各次更新仍保留原输入位置；不修改 Harness 或 pi-ai。

协议依据为 [OpenAI：对话中调整推理档位](https://developers.openai.com/api/docs/guides/reasoning#change-reasoning-mid-conversation)。插件刻意只支持协议的一部分，尤其尚未实现压缩触发后的更新重插入。

手动选择修复：已记录的 `model/selection` 是主机上的显式选择，不是未经确认的模型提议。插件录入结构化更新，并在来源元数据中关联该选择的序号，避免请求头不变或后续工具批准时重复应用旧选择。旧会话若已批准 High、之后又选择 Medium 再选择 Low，将按 Low 继续而不是失败；选择 High 则按 High 继续。插件自身不保存默认设置，原生选择器仍保留 Harness 原有的保存默认选择行为。回归测试恢复合成的旧历史，覆盖手动 Low/Medium/Max 后连续确认调整，以及录入后的并发改选；不把用户私人会话存入测试夹具。
