# Stock DSH alpha.3 and Luna Reserve retirement

This is unreleased development evidence for issue #419, based on main `66cce0142a59be68b048d356e9c43f7f198663e7`. Published Alpha 11 and its fourteen exact Host pairings are unchanged. The branch adds only exact `0.2.2-alpha.3`, not alpha.1, alpha.2, future alpha releases, mixed Host packages or a wider pi-ai range. Final exact-head CI and independent review remain required before integration; this record is not a release or Desktop/account acceptance.

## Decision and recovery

The maintainer approved retiring Luna Reserve after the stock alpha.3 routing contract proved incompatible. The Host captures provider/model/effort before `agent/pre-step` and prompt assembly. `model.select()` there affects a future step; the current step's error retry retains its captured selection. Moving the old mutation hook to pre-step or manually requeueing input would change Reserve's lifecycle. No sufficiently early public asynchronous routing/quota-recovery interface was found in the published packages. No Host patch or policy bypass is used.

Exclusive Reserve routing, permits, state and usage negotiation are removed. An old `enableReserveFallback: true` is accepted as inert migration input and resolves to false, including settings readback; it cannot create polling, negotiation headers or automatic model/account changes. The UI no longer offers the switch. Shared ordinary quota/account UI and the read-only quota tool retain the 60-second cache, identity isolation, coalescing, caller cancellation, bounded cache and failure cooldown. Foreground successful and failed refreshes revoke old observations; cache eviction and configuration changes revoke their observations too.

Legacy `gpt-reserve` is absent from the catalog. Metadata resolution, preparation, direct streaming and captured-stream entry reject it with `MODEL_RETIRED` before account access or provider dispatch. The message asks the user to explicitly select an ordinary model. If a Host cannot change the old conversation's model, preserve that conversation and start another with the chosen model. No replacement account/model/entitlement is guessed. Existing return files are neither read, migrated nor deleted. An unused factory argument position remains solely to avoid shifting unrelated compaction/governor/lifecycle arguments for older callers; it is never consulted for authority.

## Separate alpha.3 search correction

The first genuine alpha.3 installed-runtime attempt got the fallback provider instead of Codex Search. A retained purely synthetic installation identified the actual child-fiber error: the search-route owner check compared the running config against `fiber.config`. New Cordis keeps raw input there and exposes its running Volatile references as public `effectiveConfig`. The correction uses that effective object when the surface exists, otherwise the old Host's config, retaining strict reference equality. Undefined/wrong effective config is rejected even if raw input matches. Host selection changes still win, including A→B→A between searches, and disposal restores only plugin-owned changes.
