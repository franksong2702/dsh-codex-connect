# Explicit new-session speed defaults — 2026-10-20

Refs #342. This source follow-up adds independent `newSessionSpeedMode` and `newSubagentSpeedMode` settings. Each accepts Standard, Fast or Ultrafast only after explicit configuration. Omission or null preserves the corresponding legacy Fast boolean; explicit Standard can override an old true flag. More settings saves through Host revisioned mutations, uses null reset masks and keeps the old preferences available for reset. Fresh defaults and existing conversations remain unchanged.

The public `agent/created` startup event occurs before the first request/header exists. Reading that header at startup cannot identify the model. The implementation therefore captures the startup preference and a browser-safe active-account key in a bounded pending map. The first admitted `agent/request` waterfall result or the existing same-origin speed read resolves the model and uses the existing selectSpeed guards. The actual Host factory serially awaits startup listeners; no model request or entitlement probe is needed for initialization. Unsupported initial routes consume the pending intent without a paid hint; a signed-out eligible route fails explicitly and retains that failure across retries. Sign in before creating a session intended to default to Ultrafast.

Model commits (including away/back), login/logout/account commands, manual speed mutations, deletion and disposal invalidate pending intent as well as existing paid selections. An asynchronous account lookup commits only to its original pending identity and workspace/account epoch, so a stale success or failure cannot overwrite a newer manual choice. Cancellation propagates and removes its pending intent. The queue and paid control map retain the existing bounded session limit. Startup preferences are process-local choices, not durable session permissions; resume does not reapply them.

The legacy boolean GET returns 409 for a pending startup Ultrafast preference as well as a selected one, so it cannot show Standard before a paid first request. An explicit legacy Standard/Fast command cancels the pending intent. The initial account binding, exact supported model checks, live selection revision, request capture and actual dispatch account/model confirmation remain authoritative. Entitlement and actual served tier remain unknown. Auxiliary title/compaction requests do not inherit the conversation Ultrafast choice. The defaults do not add a fallback, replay, new permission, paid probe, WebSocket route or latency claim. Frozen Adaptive Task/Reserve expansion is unaffected.

They also cover pre-header UI state, old booleans/null masks, unsupported initial models, resume and manual preservation, account/model races, stale read rejection, cancellation, signed-out repeated failure, bounded pending intents, actual Host settings and UI revisioned save/reset. These checks do not establish live account eligibility or paid performance.
