# DSH 0.2.2-rc.2: independent usage-focused API review

Date: 2026-11-12. Plugin base: `b343c1fd5052dd5f6138fd885d0dae7ccae2aeed`; the accompanying JSON records SHA-256 for the current uncommitted source files inspected, not a final release identity. Official source tag: [`ddac96760b6edf8fa0fe17cbdcf0b512f4c12b2c`](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.2).

## Method and scope

Downloaded 30 pairs of official npm packages at exact `0.2.2-rc.1` and `0.2.2-rc.2`: the previous 19-package comparison scope plus 11 packages imported or used by current UI, approval, Search, timeout and path code. All 60 archive SHA-512 values matched their registry `dist.integrity`, and archive manifest identities matched. Archives were extracted as data, not installed or executed for this static comparison. The JSON records registry URLs, SRI, archive SHA-256, and added/removed/changed file names excluding source maps. Exact version strings are the only normalization used for byte comparison; a changed-file inventory is not proof that all changed semantics were reviewed.

A TypeScript AST scan located 44 runtime DSH import sites and 29 distinct module/export pairs in current `src`. All named/default exports were found in the exact rc.2 export targets without evaluating those targets. This does not substitute a typecheck against the full rc.2 graph or prove dynamic Cordis services are present.

## Findings relevant to current plugin calls

1. **Agent ownership is a real breaking change, handled by the separate candidate.** `AgentRegistry.roots/isOwnedBy` are removed. The public Subagent `rootOf(agent)` validates exact live caller/activation/root instances and rejects unmanaged delegated agents; creator `parentSession` alone cannot replace this authority. The candidate must retain old-Host ownership and explicit fail-closed recovery boundaries. This review does not independently approve that implementation; its dedicated reviewer and recovery matrices are separate evidence.
2. **Fixed model selection is not an invitation to restore Task routing.** The rc.2 deprecated `agent/request` hook must preserve provider, model and explicit/absent effort captured at preparation. Ordinary manual adapter dispatch does not rewrite this selection; automatic Task paths must remain recovery-only and reject before the old routing mutation. No new route-selection implementation is required for the frozen surface.
3. **Session batching retains the current observer contract.** `append(array)` is added, while scalar append and per-event `session/event` notifications remain. The plugin does not replace Session.append; its conversation-speed observer checks each committed model-selection event and exact live session, so a batch cannot bypass invalidation. `requestHeader`, `snapshotEvents`, `deriveMessages`, `deriveEventMessage`, and `foldSurface` remain available. No additional break was found in the inspected checkpoint/history call sites.
4. **Pi-ai adapter entry points remain.** `PiAiAdapter`, `prepareCall`, `resolveModel`, `stream`, profile/options and provider wrapping used by the plugin remain. New signed-Anthropic-thinking prefix handling and an optional observer are upstream additions; this plugin continues to use the Codex Responses provider and does not call those new APIs. The pi-ai dependency identity is unchanged between these Host packages. The review does not establish actual OAuth/model access or wire interoperability.
5. **Error/attachment/tool changes do not remove the used APIs.** Attachment errors now derive from the shared HarnessError; attachment save/load/request-target shapes used here remain. Tool guard returns gain an optional structured denial, and existing string denial remains supported. `defineTool`, `TOOL_ABORTED`, and the cancellation paths referenced by the plugin remain. LlmError's TypeScript constructor code is narrowed to built-ins, but the emitted runtime still validates a nonempty string; the existing `MODEL_RETIRED` error is not rejected at runtime. A future source build directly against rc.2 declarations should revisit that type-only narrowing rather than assert a runtime crash.
6. **HTTP/approval/settings core surfaces remain.** Inspected WebServer, connection, approval and config-form declarations retain the methods used by the plugin. Session client history gains optional deferred loading, which this plugin does not call. Remote account/Office registrations changed, but the plugin uses its own account endpoints and does not import the removed account/Office remotes.
7. **Search remains Host-owned.** `dsh-web` gains a remote provider list and optional display metadata; its search/fetch provider registration and selection methods used here remain. The plugin must not infer that upstream default Search-provider migration permits changing the user's selected provider.
8. **Menu anchoring changed; isolated rc.2 browser evidence is now available below.** `Menu.getAnchorRect` is removed in favor of `anchorRef` / CSS anchors. The current speed control passes the old property; rc.2 ignores it, but its embedded `anchor` is wrapped by the primitive's own CSS-anchor root, so static inspection alone does not demonstrate broken placement. Do not silently replace the property in a way that breaks legacy Hosts. Test the exact rc.2 primitive with speed selection, intrinsic disclosure resizing, viewport edges/scroll, keyboard and pending-effort behavior before declaring UI compatibility. Modal's existing props, the used model-directory snapshot contract, and the `conversation.input.right` / image turn-tail contracts remain available in the inspected declarations.

## Conclusion and limits

No additional confirmed blocking API defect was identified in these inspected ordinary-use call sites beyond the known ownership/fixed-selection transition. The separate browser stage below addresses Menu geometry, not full Host/Desktop acceptance. Full same-artifact Host installation, actual rc.2 recovery/crash/ordinary-request fixtures, browser results, final-head CI and independent patch review must be cited separately. This static review performed no account access, model request, daily-profile installation, service restart, publication, native UI interaction or Desktop acceptance. Computer Use #402 remains out of scope and closed.


## Separate isolated rc.2 Chromium fixture stage

The official SRI-verified rc.2 primitive compiled bundle was executed in a disposable workspace with fake fetch responses, no real provider. Speed-control source was copied unchanged: legacy getAnchorRect remains, no new Menu anchorRef is passed. Approved normal escalation was needed after macOS sandbox denied Chromium MachPort startup.

First run: **11 passed, 3 failed**, all from the legacy <=145px width assertion. rc.2 renders **146px**; bottom-right upward positioning/alignment/bounds had passed. This is a Host style width difference, not a lost-anchor defect.

Only in the isolated test copy, width limit 145 was changed to 146, retaining all other geometry assertions. Two scroll-container cases at 320 and 390px were added. Final: **16/16 passed**, two files, 6.04 seconds. Coverage includes en/zh selection/disclosure, bottom-right and bottom-left containment, large-font narrow-screen disclosure, focus/keyboard and pending-effort behavior, and popup following a 100px scroll of the embedded composer anchor. No production code was changed. Existing rc.2 internal CSS anchoring works for these cases; no compatibility source patch is recommended without a reproduced defect.

See dsh-022rc2-ui-fixture-review.json for exact identities and hashes. Two additional SRI-verified code-language archives supplement the 60-archive static review. Actual rc.2 primitive execution is not full rc.2 Desktop acceptance: other services/dependencies remain synthetic or existing fixtures; production theme, OAuth, real model calls, native WebView and live Host behavior remain unverified.
