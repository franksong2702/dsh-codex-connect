# Terra Computer Use local candidate — 2026-10-28

Status: partial implementation, not deployable. No daily service, live model, desktop, actual credentials, system permission or application grant was changed. A native binary was compiled in isolation and never executed. Existing installation remains intact. No release or merge occurred.

## Implemented boundary

The private, default-off `packages/dsh-codex-computer-use` companion uses published DSH `0.2.2-alpha.2` APIs: a fresh owned Agent with a fixed Terra route, empty dedicated preset, scoped Native executor and standard guarded tool pipeline. The parent selection is unchanged. The Host owns application consent, revocation, image preparation and native operation lifecycle. There is no root impersonation or general program transport. One call per child batch makes result-dependent policy state authoritative before the next operation. Cancellation, deadline, budgets and an exclusive lease close the run; uncertain cleanup retains the lease.

The current mitigation admits only exact-app `getApp`, configured-window screenshots, unmodified left coordinate clicks and window scrolling. AX observation, every indexed action and text entry are denied. This is not the complete requested AX/form capability and cannot be described as equivalent to native Computer Use.

## Two Host contracts remain unresolved

1. **Existing Reserve compatibility.** The stock installer refuses the original candidate on the new exact Host and restores the isolated profile. A local, explicitly adapted declaration candidate then installs through normal checks with no exemption. Its installed runtime contract fails the existing Reserve regression: no expected Reserve request header is committed. Published `dsh-agent` documents `agent/request` as deprecated and forbids changing its captured provider/model/effort; `dsh-agent-loop` enforces this in `prepareRequest`. `agent/pre-step` already receives the captured selection. `agent.model.select()` changes a future step, and request-error retry reuses the prepared choice. No supported asynchronous pre-selection/retry hook preserving existing behavior was found. Rejecting/requeueing a step and changing selected models would alter semantics. Rewriting an adapter's outgoing route would misstate logged route/budgets. Neither was implemented. The attempted declaration changes were reverted; the current Connect contract still ends at `0.2.1-rc.4`, and verified-compatibility was not extended.
2. **Window-bound AX.** The published macOS provider intentionally exposes application AX roots within window observations. `AXAccess.project` retains non-window roots and indexes actionable menu items before collapsing menu descendants. `AXWorker` resolves indexed actions by app/snapshot/index, and direct AX actions do not require owning-window equality. The public CUA result strips structured elements and offers no authoritative per-element window proof. Display-tree filtering or a snapshot allowlist cannot repair this boundary. The plugin therefore denies the entire unsafe route before transport. Native/source behavior was inspected only; no real AX action was attempted.

Those two extensions were subsequently explicitly authorized for the local instance and are now implemented as isolated source patches in `host-patches/codex-cua-local.1`. The native source includes mutation-time checks and delayed AXRaise; all state-parser copies preserve the strict-window attestation. The builder produces a distinct `0.2.2-alpha.2.codex-cua-local.1` package closure, retaining original sources. The route kernel's four synthetic behavior cases passed. The first installed Connect integration still failed because its older SDK copy hid the new capability; detection now uses the live AgentRegistry service, with the full installed rerun pending. The companion's AX path remains disabled until that integration and review are complete. Local candidate versions are listed separately from stock supported versions; the unpatched alpha.2 release remains unverified.

## Validation and limits

- The owning package's Host tests run with the real published Agent loop/preset registry/Native pipeline, an in-memory scripted model and synthetic CUA transport. The official CUA consent refusal uses its actual `installCua` implementation with a fake byte channel. Window/menu variants, grouped calls, stale completion observations, cancellation, in-flight Host-reported revocation and lease loss have regression coverage. No actual screenshot or live application operation is established by these tests.
- The first root `pnpm run check` reached tests after passing workflow contracts, lint and both typechecks. Sandbox loopback listeners failed; that failure is retained. The same synthetic test suite was then submitted through normal `require_escalated` tool approval and approved: 171 files, 2,380 passing tests, two existing skips. No port or service entry was changed to evade a refusal. Build, environment/isolated imports, CLI/request-metrics/compatibility and package checks passed separately. This is component evidence, not a claim that the original failing command succeeded.
- Browser tests initially could not find the pinned browser executable. A task-local headless Chromium download was used with isolated test contexts: 14 files, 97 tests passed. No personal browser profile was used.
- A second independent read-only security review found and verified closure of explicit menu input, stale observation and multi-call state-ordering gaps. The remaining inability to safely support AX/text is a functional blocker, not an accepted feature reduction.
- A rollback command was prepared privately and syntax checked, but no backup, rollback or deployment ran. Cutover still requires a verified cold backup, independent review, exact-commit CI and parent approval of the deployment gate.
- The earlier native five-task pilot has unknown effective model/effort, and there are no custom live results. It remains observational; no parity or performance acceptance is claimed.
