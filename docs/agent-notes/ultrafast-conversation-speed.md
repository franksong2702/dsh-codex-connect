# Explicit conversation Ultrafast — 2026-10-19

This source change addresses #342. Standard omits the speed hint; legacy Fast sends `priority`; an explicit Ultrafast choice sends `ultrafast` only on exact provider `openai-codex` and exact models `gpt-6-astra` / `gpt-6.1-sol`. Neither effort nor model/output settings change. New-session/subagent Fast defaults retain their existing behavior and cannot seed Ultrafast. Auxiliary compaction/title calls do not inherit it.

A later source follow-up makes that compact menu the only Composer speed control for Codex GPT models. Models outside `gpt-6-astra` and `gpt-6.1-sol` previously fell back to the pre-menu one-tap legacy Fast button plus a bare native `<button disabled>Ultrafast</button>`; a live subagent session on `gpt-6-luna` showed that fallback rendering as an unstyled pill in the mobile Composer. Those models now share the same menu: Standard and Fast stay selectable, only the Ultrafast entry is disabled, and its reason distinguishes missing model support from a missing account or selection. The blocked reason is not left in a disabled button's hover title: review found that a disabled row cannot be focused and never receives hover on touch, so the applicable reason now prefixes the same in-flow disclosure the information action reveals and that `aria-describedby` links to, with the standing quota text after it. The route contract, server gating and request projection are unchanged; only the Composer rendering and the disabled-row copy changed.

The Alpha8 conversation-only delivery did not implement the issue's proposed Ultrafast session/subagent default settings. The subsequent source implementation is documented separately in [new-session speed defaults](new-session-speed-defaults.md). Finite SSE remains the supported policy; there is no WebSocket transport change or measured latency-gain claim in this PR. Those proposals are not delivered by the selector.

The existing bounded process-local Fast registry remains the compatibility surface. A separate bounded control map adds account-key, plugin-instance, live-session incarnation and model-selection revision binding. The Host's global `session/event` feed observes only future `model/selection` metadata; no prompt/history scan or persistence is added. Missing live lookup fails closed. Login/logout/account commands invalidate control generations without changing saved Fast preferences. Normal captured-account auth resolves the bearer; only the existing opaque account hash enters request-local AsyncLocalStorage and is cleared at stream termination. Pending requests cannot acquire a later account's paid choice.

The same-origin Connection-authorized enum route validates bounded strict input and compare-and-set generation/revision. Old POSTs are rejected rather than replayed. Views do not own the shared session choice: ordinary unmount/navigation only cancels that view's pending request, and DELETE is not supported. Only actual Host model/account lifecycle changes invalidate scope. Reopening the same conversation preserves its choice and generation. A boolean Fast write explicitly replaces Ultrafast; its GET returns 409 for a current Ultrafast choice, preserving honest legacy readback. The final payload projection runs after a previous callback's replacement and rejects model mismatch. Expiry stays sticky across Host retries until a fresh explicit control read/choice.

Independent review found that an earlier candidate deleted a shared generation on view unmount, which could clear another view's newer revision. Two regressions using the real shared registry reproduced the server/UI disagreement and navigation loss before the fix. The UI fixture now preserves GET state/generation and exercises compare-and-set POSTs instead of inventing a fresh Standard state on each read. Shared-view unmount and navigation return preserve Ultrafast; real model/account scope changes still invalidate it. The unversioned DELETE path was removed as part of this repair.

A second review found that merely changing the Host selection revision left an old Ultrafast control behind: on an unsupported new model, the real legacy Fast GET stayed at 409 and normal requests failed with an expired scope. The committed Host model-selection feed now both advances the revision and retires that session's old control, preserving the legacy Fast preference. It checks the live Session object before clearing, so a different incarnation with the same id has no authority. Captured old requests still fail their scope guard; a new request after an explicit model/account lifecycle change starts with the effective Standard/Fast default. This is not error-triggered fallback or replay. The UI tests now use real protected route handlers and the actual SessionStore feed, and transport regressions exercise the ordinary pi-ai SSE request before and after the lifecycle change with synthetic credentials.

Model support is separate from billing entitlement. Eligibility remains unknown; there is no remote discovery, plan inference, OAuth scope change, SIWC token reuse, private endpoint or paid probe. Cached/built-in `model/list` absence is not a denial. The pi-ai response callback exposes only HTTP status/headers, so this implementation deliberately retains **unverified served tier**, including after HTTP200 or a completed response. It adds no SSE body observer or entitlement cache. It must never claim account eligibility, actual billing, latency improvement or accepted Ultrafast from a request hint. Existing provider/Host retries are not disabled or extended; the feature adds no generation replay or silent tier fallback.

Offline validation covers exact-model payloads, real pi-ai SSE transport with synthetic credentials, account/auth races, Host model-selection away/back, stale mutation/eviction, strict HTTP admission, legacy Fast commands/defaults, auxiliary exclusion and Chromium controls in both languages. Synthetic successful responses prove transport and local UI only. Real OAuth served tier, account qualification, billing and latency remain untested. No package publication or daily service update is included.
