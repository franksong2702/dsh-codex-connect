# 0.2.0-alpha.13

English | [中文](#中文)

Alpha 13 is published for exact stock DSH `0.2.2-rc.1`, retaining the fifteen prior exact Hosts. Public installation guidance now recommends Codex Connect `0.2.0-alpha.13` / DSH `0.2.1-rc.5`. The additional rc.1 pairing is bounded isolated evidence, not a request to upgrade the daily Host. The plugin `latest` channel remains `0.2.0-alpha.10`.

- **One exact additional Host:** retain the prior fifteen declared versions and add only `0.2.2-rc.1`. This does not infer support for other prereleases, future versions, or mixed DSH package sets. Version gates, peer declarations and installed-package checks remain exact.
- **Saved Task recovery stays restricted:** both `0.2.2-alpha.3` and `0.2.2-rc.1` use the recovery-only profile. Inspection, authenticated Stop/manual takeover and the existing checked disable/archive exits remain. Automatic routing, resume and delegation recovery fail closed. Existing ownership, session, revision, receipt, ledger and child-cleanup checks remain. The original fourteen Hosts retain their prior contract; Task public activation and all optional defaults stay off.
- **Safer compatibility fixtures:** resolve each exact Host installation without weakening peer checks. Bound transient registry retries and reject malformed metadata rather than treating it as a supported version.

- **Locked dependency validation:** use patched Zod `4.6.7` in the build/test lockfile for [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), without changing package or peer ranges. This does not upgrade a user's Host or certify every Host-owned dependency.

## Verification and migration boundaries

[Alpha 13](https://github.com/franksong2702/dsh-codex-connect/releases/tag/v0.2.0-alpha.13) is published from `cc0b9ba5c75ea9c9d77e349bf112d2b5ae1e1c47`, after [exact-release main CI](https://github.com/franksong2702/dsh-codex-connect/actions/runs/42585124305) and [protected OIDC publication](https://github.com/franksong2702/dsh-codex-connect/actions/runs/42587933168) succeeded. Independent readback on 2026-11-09 confirmed npm version/alpha as `0.2.0-alpha.13`, the matching source tag and non-draft prerelease, and unchanged `latest` as `0.2.0-alpha.10`. Read-only `recover-release` verification returned `already-complete`: the public npm archive matches the original workflow artifact byte-for-byte and agrees with registry SHA-512/SHA-1. SHA-256 is `dd78a98c20faadb24db413d8c4bebab7d35d90d2c30d1b955349fe5e90b19859`, 74 files / 1,478,347 bytes. This is the same archive used by all sixteen exact-Host installation checks; see the [verification record](https://github.com/franksong2702/dsh-codex-connect/issues/423#issuecomment-6736029896). These isolated synthetic checks do not establish real-account/model, native GUI, Windows Desktop, performance or daily-installation acceptance. No republishing, tag promotion or Host upgrade was performed.

Install the exact plugin version only for a supported exact Host from [INSTALL.md](../../INSTALL.md), replacing `web` only with the intended existing profile. This does not authorize a Host upgrade.

```sh
dsh plugin --profile web add dsh-codex-connect@0.2.0-alpha.13
```

Isolated synthetic checks do not establish real-account/model, native GUI, Windows Desktop or performance acceptance. No daily Host upgrade, service restart, account reauthorization or new permissions are required or performed by this release. Preserve saved sessions, Task state, return files and OAuth credentials. On recovery-only Hosts, inspect and stop or take over old Task state through authenticated controls; do not attempt automatic resume. Computer Use #402, unrelated dependency updates and the unresolved replacement Auto-review backend in #417 A are not included.
