# 0.2.0-alpha.3 — official Desktop sign-in compatibility

This Alpha delivers [PR #317](https://github.com/franksong2702/dsh-codex-connect/pull/317). Official DSH Desktop opens the validated HTTPS authorization challenge externally without first requesting the rejected `about:blank` popup. Electron's null external-window handle does not block the sign-in flow; manual recovery and cancellation remain available. Desktop account-request rejection shows restart/version diagnostics rather than a Web-only origin-trust command. Ordinary Web popup behavior is preserved.

## Installation

For an existing Web profile, substitute its name for `web`:

```sh
dsh plugin --profile web add dsh-codex-connect@0.2.0-alpha.3
```

For official macOS Desktop, initialize its profile once, then fully quit Desktop before using its bundled CLI with the intended `DSH_HOME`:

```sh
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add dsh-codex-connect@0.2.0-alpha.3
```

Reopen Desktop after installation and verify plugin activation. Preserve default models, profile patches and account state. A Web profile installation does not enable the plugin in Desktop. See [the installation guide](../../INSTALL.md#official-desktop) for the scoped pnpm 11 optional-build-script workaround.

The five exact declared hosts remain `0.1.7-rc.1`, `0.1.7-rc.2`, `0.2.0-rc.1`, `0.2.0-rc.2` and `0.2.1-alpha.1`. This release does not add DSH `0.2.1-alpha.2` support or require a host upgrade. npm `alpha` is `0.2.0-alpha.3`; `latest` remains `0.2.0-alpha.1`. Existing npm versions are immutable; the packed README retains the prior pre-publication recommendation.
