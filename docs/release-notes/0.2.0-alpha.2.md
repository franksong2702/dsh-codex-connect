# 0.2.0-alpha.2 — exact DSH compatibility and image edit handles

This Alpha packages the already-merged cross-route image selection handle bridge (#302) and the exact DSH `0.2.1-alpha.1` compatibility repair (#304). It does not upgrade the model/OAuth library, change account behavior, enable experimental features, or promote the plugin to a stable release.

## Changes

DSH `0.2.1-alpha.1` removes runtime invariant discovery and its invariant package. The plugin drops that obsolete type-only runtime peer while retaining its baseline development dependency and legacy invariant export for older hosts. The declared exact hosts are `0.1.7-rc.1`, `0.1.7-rc.2`, `0.2.0-rc.1`, `0.2.0-rc.2`, and `0.2.1-alpha.1`; later Alpha or stable hosts remain unverified. Published `0.2.0-alpha.1` is unchanged and does not support the new host.

When image generation is explicitly enabled, non-Codex routes receive persistent image selection handles on image tool results. Repeated projection preserves one canonical handle. Codex routes retain their existing request-time projection; unknown routes receive no bridge. `imageHandleBridgeTools` can restrict the participating tools. This does not enable image generation or grant access to unrelated images.

## Installation after publication

Use an existing profile name in place of `web`:

```sh
dsh plugin --profile web add dsh-codex-connect@0.2.0-alpha.2
```

This command identifies the new package only after publication. Release preparation keeps the public README recommendation on the previously published pair. Publication updates only npm `alpha`; `latest` remains `0.2.0-alpha.1`. No daily or test service upgrade is included.

## Verification boundary

Release gates require the complete check, browser regressions, and the five-host strict installed matrix against identical packed bytes. Fixtures use synthetic credentials and provider responses, including the host's image-tool waterfall; they do not establish live OAuth, paid quota, actual cross-model image editing, authenticated new-host browser acceptance, or physical Windows/mobile acceptance. Recorded exact pairings remain in [the compatibility catalog](../../verified-compatibility.json).

See [#302](https://github.com/franksong2702/dsh-codex-connect/pull/302), [#304](https://github.com/franksong2702/dsh-codex-connect/pull/304), and [the compatibility investigation](../agent-notes/dsh-021-compatibility.md). Adaptive Task and other frozen research remain paused; existing permissions, defaults and recovery obligations are preserved.
