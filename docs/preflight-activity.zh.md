# 有界的 bili 预处理活动

[English](preflight-activity.md) | 中文

这项源码改动处理 [#340](https://github.com/franksong2702/dsh-codex-connect/issues/340)：bili 代理压缩请求时可能超过普通流的五分钟空闲期限，同时持续发送 `: bili-preflight` SSE 注释。注释不是模型输出。只有运维者明确指定一个可信代理 origin 和有限总预算，才会启用此适配。已发布的 Alpha 5 保持不可变，不包含本次改动。

## 配置

在实际生效的 profile 中给已有插件条目添加启动配置。把示例地址换成插件实际使用、不带凭据的 HTTP(S) 代理 origin。`preflightActivity` 不是浏览器设置；插件加载时会校验它。

```yaml
- id: llm-openai-codex
  config:
    enableProxy: true
    proxyUrl: http://127.0.0.1:7890
    preflightActivity:
      protocol: bili-v1
      trustedProxyOrigin: http://127.0.0.1:7890
      maxDurationMs: 450000
```

`maxDurationMs` 必填，必须是大于零且不超过 `2147183647` 的安全整数。上限为宿主内部的有限保险计时器预留 300000 毫秒，并不是建议的等待时长。省略 `preflightActivity` 即保留原有行为。修改会在之后由运维者控制的插件加载中生效；安装补丁不会自动修改或重启服务。

## 计时与信任

认可活动必须明确配置 `preflightActivity`，且成功的 SSE 响应带有 `x-bili-preflight: compressing`。本次调用必须取得配置中的代理 origin；若未取得插件代理，则必须证明已安装的 billion-context 原生 fetch 链确实将本次响应路由到同一配置 origin。原生证明要求安装标记、fetch 自身的链标记、当前原生状态对象中带显式端口的数字回环 HTTP origin，以及将本次请求改写为 `<origin>/bili/<input URL>` 后的精确未重定向响应 URL。只有响应头或仅安装了 billion-context 均不能授权路由。

使用原生拦截时，`trustedProxyOrigin` 必须填写当前原生代理的精确 origin（包括端口）；这一独立安装的路由不要求 `enableProxy`。动态分配的端口必须匹配启动授权。原生代理重新加载或替换后，旧响应失去心跳授权；不同端口需要运维者在后续插件加载时更新配置。即使原生拦截已安装，省略 `preflightActivity` 仍会关闭适配。已经取得另一个插件代理时，不会通过原生回退绕过不匹配。

通过验证的响应头只续期当前空闲读取一次。随后必须是恰好由 `: bili-preflight` 和空行组成的完整帧才认可活动。允许分片的 LF、CRLF 和 CR 换行。不可信直连、其他代理、普通注释、不完整帧或包含其他字段的注释均不会续期。代理信任不会改变目标地址校验、重定向策略、TLS 校验、凭据或禁止静默直连回退的策略；不可信路由中的这些响应头不能证明代理身份。

等待输出读取时，普通空闲期限仍为 300000 毫秒。认可的心跳只续期这一空闲期限。另一个不可续期的预处理总预算从第一个符合条件的响应头开始，重试和后续心跳都不能重置。出现 `data:` 行或超长帧后停止识别心跳，但不会抹除总预算。宿主转换出的第一个数据块、EOF 或迭代器清理结束预处理计时。消费者在两次读取之间暂停，不算提供方空闲。

插件复用现有的公开提供方认证、流配置接口与 `dsh-timeout`，不需要 fork 宿主或新增上游接口。计时从宿主凭据与附件准备完成后开始。只有明确启用的 profile 才将内部保险期限设为 `300000 + maxDurationMs`；外层插件仍对普通请求强制执行五分钟空闲限制，包括直连与不符合条件的响应。每个迭代器的授权与计时独立，同一 prepared call 的重复调用也不共享。

用户取消时保留宿主已经产生的 usage 与 aborted-finish 数据块。取消后仍不结束的读取，最多等待一个事件循环轮次便停止等待。插件自己的期限先到时始终报告 `TIMEOUT`，不会被提供方随后产生的 aborted finish 改写。清理会取消请求、移除自身计时器，并停止等待卡住的内部 return；不能强迫任意第三方回调结束。响应字节和读取需求保持不变，不向模型输出或会话历史注入虚构心跳。

## 验证与限制

`tests/preflight-*.spec.ts` 在未修改的最旧开发宿主上使用虚构凭据、实际 SDK 解析和虚拟时间，覆盖分片帧、缓慢准备、取消、总预算／空闲期限与响应读取。`tests/native-preflight.spec.ts` 验证严格的原生安装授权契约，包括真实本地 fetch 的精确响应元数据、重定向拒绝与授权替换；适配器测试覆盖已配置原生路由、默认关闭、origin 不匹配、旧授权、有界心跳、取消以及模型输出后的空闲期限恢复。`pnpm run check:dsh-matrix` 对每个精确声明的宿主安装同一个插件包，每个宿主执行六项启用／默认关闭检查，包括第 299 秒到达的响应头之后仍有完整 450 秒预算，以及启用／关闭时的取消结果对照。已安装包检查只替换 HTTP 和代理传输，不调用真实提供方。

这些检查不代表真实 bili、HTTPS CONNECT／TLS 拓扑、Windows Desktop 或账户／模型验收。此补丁不处理 issue 中取消后另行发生的 HTTP 413。原生兼容性跟进 #405；独立的 HTTP 413 需要 bili 上游修复及真实场景验收。源码合并和绿色 CI 都不等于发布或真实对话成功。
