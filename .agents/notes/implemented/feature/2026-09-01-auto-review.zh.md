# Agent Note：由宿主审批链承载的自动审查

状态：已实现

## 问题

[Issue #84](https://github.com/franksong2702/dsh-codex-connect/issues/84) 要求在 Codex Connect 中实现 Codex Auto-review。此前的 [PR #88](https://github.com/franksong2702/dsh-codex-connect/pull/88) 只证明隐藏审核路由能返回预期结构字段；能力探针不能授权真实 Harness 动作，也不能保证审批、重试、拒绝和审计语义。

## 决策

Codex Connect 在既有 `approval/request` waterfall 中安装一个默认关闭的回答器。Harness 审批策略仍然先执行。关闭时，监听器不会访问网络或修改状态，而是直接委托后续回答器。开启时，它先要求当前请求提供方是 `openai-codex`，再把请求解析为唯一的已保留 `tool/call`，构造有界且标明信任来源的上下文，并通过已保存的 ChatGPT OAuth 路由调用隐藏审核器。其他提供方的会话始终委托后续回答器。

只有完整严格的允许结果才返回 `allowed-once`。任何本地歧义和后端失败都委托后续回答器。拒绝返回 `rejected`，注入理由和禁止绕行指引，并计入当前轮熔断器。超时与取消保持不同语义。熔断阈值与官方的连续三次拒绝、最近五十次中拒绝十次一致。

一次性人工覆盖使用可选的 `/approve` 命令。它跨后续 turn 保留工具名、规范化 JSON 参数和工作目录的 SHA-256 指纹。下一次审批无论匹配与否都会消费覆盖；只有匹配时返回 `allowed-once`。最近拒绝元数据保存在内存中，最多十条。

Harness 已持久记录审批问题、审批结果和命令生命周期，因此插件不再建立一套重复原始参数的审计事件。日志只包含动作指纹和结构化评估标签。

设置界面常驻简短说明，把完整的数据和失败处理告知放入可展开区域，并在每个 profile 首次启用前要求确认一次。确认状态与功能开关分开保存，因此关闭自动审查后，更换浏览器也不会再次要求确认。

## 后果

启用设置表示用户明确允许把有界的审批上下文、工具参数、工作目录和待执行动作发送到 `chatgpt.com`。隐藏推理和已保存凭据会被排除。Auto-review 是 Codex 官方能力，但 OpenAI 没有承诺隐藏 OAuth 路由是稳定公共 API，因此路由不可用时回到人工审批，既不会停止所有工作，也不会放行动作。

命令集成保持可选，因为 profile 可以组合审批服务而不组合 `dsh-commands`。这种 profile 仍可自动允许或拒绝；精确人工重试通过既有人工审批路径处理，而不是 `/approve`。
